Write multi: a receiver that serves several senders at the same time, the Go way, with one goroutine per connection.
What you should know
  • go f(x) runs f in a new goroutine and returns at once, so the accept loop can take the next connection while earlier ones are still being served.
  • A sync.WaitGroup waits for them all: wg.Add(1) before each go, defer wg.Done() inside, wg.Wait() at the end.
  • Underneath, on Linux, the Go runtime runs the epoll loop of the previous page for you.

The spec

CommandBehaviour
multi PORT NListen on PORT, accept N connections, store connection k (in accept order, from 1) in in-k.bin, each served by its own goroutine. When one ends, print k: received B bytes from ADDR. Exit with status 0 when all N are done.
Errorsserve's error is printed by main as multi: …, exit status 1.
Goroutines, in two lines go handle(k, conn, name) // starts now, runs alongside; the loop continues at once wg.Wait() // sleeps until every wg.Done() has been called

Since Go 1.22 each loop iteration has its own k and conn, so a goroutine started in the loop keeps the values of its own iteration.

Run this

$ multi 9000 2 $ sleep 3 | nc -N $B_IP 9000 & $ gosock send $B_IP:9000 /tmp/big.bin $ ls -l in-1.bin in-2.bin

What you should notice

  • "2: received 2097152 bytes" came first, while connection 1 was still open and silent.
  • "1: received 0 bytes" 3 seconds later, then multi exited.
