What you should know
  • Each write can become its own segment. 100 writes of 1 byte can cost 100 segments, each with 40 bytes of headers.
  • Nagle's algorithm: while sent data is not yet acknowledged, small writes wait and are sent together. It is on by default in Linux.
  • TCP_NODELAY turns it off, for programs where every byte is urgent. Go turns it off on every connection; SetNoDelay(false) turns it back on.
When Nagle hurts

Nagle trades latency for fewer segments: a small write may wait up to a round trip. Combined with the receiver's "delayed ACK" (Linux waits up to 40 ms before acknowledging, hoping to piggyback the ACK on a reply), a request written in two small pieces can stall for 40 ms. Interactive protocols set TCP_NODELAY; Go's authors chose it as the default for everyone.

The better fix is in the program: build the message in memory (or use a bufio.Writer) and write it once. These machines model Nagle but not delayed ACKs.

Run this

chatty sends 100 bytes in 100 writes. Build it. Give A's link a 20 ms delay (a round trip worth waiting for), and record B's segments to a file:

 $ sudo tc qdisc add dev eth0 root netem delay 20ms $ tcpdump -n port 9000 > d1.txt & $ nc -l 9000 $ chatty $B_IP:9000 $ pkill tcpdump $ grep -c 'length [1-9]' d1.txt $ tcpdump -n port 9000 > d2.txt & $ nc -l 9000 $ chatty -nagle $B_IP:9000 $ pkill tcpdump $ grep -c 'length [1-9]' d2.txt $ sudo tc qdisc del dev eth0 root

What you should notice

  • Go's default: 100 segments with data, one per write.
  • With Nagle: a handful. The first byte left alone, the others waited for its ACK and travelled together.
