A server called listen but never calls accept. A client calls connect. What happens? connect waits until the server calls accept. connect returns: the server's kernel completed the handshake, and the connection waits in the accept queue. connect fails with "connection refused". The client's kernel retries until accept is called.

After listen the kernel answers handshakes alone; accept only takes finished connections from the queue (while the queue has room).

 ss -tln shows a listening socket with Recv-Q 3 and Send-Q 2. What do the numbers mean? 3 bytes received, 2 bytes to send. 3 clients refused, 2 accepted. 3 connections being handled by the program, 2 waiting. 3 connections waiting in the accept queue; a backlog of 2.

For a listening socket, Recv-Q is the accept queue's length and Send-Q the backlog. Linux keeps up to backlog + 1.

 Which side of a TCP connection ends in TIME_WAIT? The side that closed first. Always the server. Always the client. Both sides, for 60 seconds each.

The first FIN's sender keeps the connection 60 seconds in TIME_WAIT; the other side's socket disappears after its own FIN is acknowledged.

 A program sets SO_RCVBUF to 4096 and reads it back with getsockopt. What does it get? 409620488192131072

Linux doubles the request (room for its own bookkeeping) and reports the doubled value.

 A raw-syscall server restarts right after serving clients, and bind fails with "address already in use". Nobody else listens on the port. Why? The old server process is still running. The server closed its connections first; they are in TIME_WAIT and hold the port, and the new socket has no SO_REUSEADDR. The port was given to a client as an ephemeral port. The kernel needs a minute to free any port after a program exits.

TIME_WAIT connections keep the port; SO_REUSEADDR on the new listening socket lets it bind next to them.

 After one client, a server holds a listening socket and an accepted one. Which one carries the client's data? Only the accepted socket. Only the listening socket. Both, half each. The listening socket, until the program calls read.

The listening socket only produces connections; each accepted socket has its own buffers and state.

 In tcpdump, Flags [F.] means… a failed segment, to be sent again. the first segment of the connection. a segment with data that must be delivered at once. a FIN (no more data from this side), with an acknowledgement.

F is FIN, . is ACK. S is SYN, P push, R reset.

 For a connected socket, ss shows Send-Q 87040. What is it? Bytes the program has asked to send but the kernel refused. Bytes received and not yet read. Bytes the program wrote that the peer has not acknowledged yet. The size of the send buffer.

Send-Q is data in the send buffer: written, and kept until the peer acknowledges it (in case it must be sent again).
