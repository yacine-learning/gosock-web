What you should know
  • A failing system call returns -1 and an error number, errno: 2 is ENOENT (no such file), 21 is EISDIR (is a directory)…
  • In Go, that number is the error itself: a syscall.Errno. err.Error() is its text; errors.Is(err, syscall.ENOENT) tests for one failure in particular.
  • When err is not nil, the other result is meaningless. Look at err first.
Where the text comes from

The kernel only returns the number (as a negative value, -2 for ENOENT). The C library, or here Go, turns it into "-1 and errno = 2" and keeps a table of texts: "no such file or directory" for 2. strace prints all three: = -1 ENOENT (No such file or directory).

Which errors a call can return is part of its contract, listed in its manual page (man 2 open, section ERRORS). Error numbers are the same for every program on the machine, which is why the shell, cat and your Go program print the same words.

The same failure can arrive at different calls. Opening a directory for reading succeeds; it is the read that fails with EISDIR.

Run this

$ rawcat /nope $ strace rawcat /nope $ rawcat /tmp $ cat /nope

What you should notice

  • openat(…) = -1 ENOENT: in the trace, the failure is a result like any other.
  • rawcat /tmp got through open and failed at read, with errno 21.
  • cat and rawcat print the same text: it comes from the number.
