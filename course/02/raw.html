What you should know
  • Go's syscall package has one function per system call: syscall.Open, Read, Write, Close…
  • They speak the kernel's language: a descriptor is a plain int, a read fills your buffer and returns a count, a failure is an error number.
  • os.File and fmt are layers on top of these calls. The kernel sees the same write either way.
Why go down a level

In module 1 the standard library chose for you: how big each read is, when to retry, which calls to make (it even picked sendfile). That is what you want in real programs. To learn what the kernel does, you want the opposite: nothing between your line of code and the system call. In this module every call you write is exactly one line in strace.

The syscall package is frozen in Go's standard library; new programs that need raw calls use golang.org/x/sys/unix, which has the same functions with the same names. This page uses syscall because it needs no download.

Run this

rawcat is cat made of four system calls. Open it, read it, build it. Then trace it next to the real cat:

 $ strace rawcat /tmp/hello.txt $ strace cat /tmp/hello.txt

What you should notice

  • rawcat's trace is its source code, line by line: openat, read(3, …, 4096), write(1, …), the read that returns 0, close.
  • The 4096 is your buffer size. cat asked for 131072 at a time: a choice, not a rule.
