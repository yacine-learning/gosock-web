What you should know
  • read(fd, buf) returns at most len(buf) bytes, often fewer: what a terminal line, a pipe or a socket has right now. Only 0 means the end.
  • write(fd, b) can also take fewer bytes than you give it, and say so in its result. A full disk does it: a short write, then ENOSPC.
  • So reading is a loop, and writing is a loop too (writeAll).
When a write is short

A blocking write to a socket or a pipe usually waits until everything is taken. It returns early when there is no more room and waiting cannot help (a full disk), when a signal interrupts it after some bytes were copied, or in non-blocking mode, which a later module shows. Each time, the result is the truth: "I took N bytes". The rest is still in your buffer, and it is your job.

Reads are short all the time. A terminal hands over one line per read; a socket hands over what has arrived. Code that assumes "one read = one message" works on a test machine and fails on a real network.

/mnt/small on these machines is a 1 MB disk, there to make writes run out of room.

Run this

A short read. Run the first line, then type two lines in terminal A and press Ctrl+D:

$ strace -e trace=read rawcat

A short write, then a full disk:

$ df -h $ strace -e trace=write cp /tmp/big.bin /mnt/small/big.bin

What you should notice

  • Each line you typed came back from its own read(0, "…\n", 4096): 4096 asked, a few bytes given.
  • One write returned less than it was given, and the next one -1 ENOSPC. cp noticed both.
