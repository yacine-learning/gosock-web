What you should know
  • The kernel keeps file contents in memory, in 4 KB pages: the page cache. Every read copies from it.
  • A page that is not there yet comes from the disk first (a miss, slow); the next read of it is a hit, a memory copy.
  • "buff/cache" in free is that memory: used, but given back as soon as programs need it.
Tools, and the disk of these machines

fincore FILE tells how many of a file's pages are in the cache (it asks the kernel with mincore). free and /proc/meminfo give the totals. echo 3 | sudo tee /proc/sys/vm/drop_caches throws away every clean cached page, so the next read is a miss again: only root may do it, and real machines rarely need it.

The simulated disk reads about 20 MB per second, a slow disk, so the difference is easy to see. A real SSD is 50 to 100 times faster, and memory is faster still: the gap remains.

A read, in simplified kernel C ssize_t filemap_read(struct file *f, char __user *buf, size_t n) { struct address_space *m = f->f_inode->i_mapping; // the file's cached pages pgoff_t index = f->f_pos / PAGE_SIZE; struct page *page = find_get_page(m, index); // a hit? if (!page) page = read_page_from_disk(m, index); // a miss: the process sleeps here copy_to_user(buf, page_address(page) + f->f_pos % PAGE_SIZE, n); f->f_pos += n; return n; }

Run this

$ fincore /tmp/big.bin $ time cat /tmp/big.bin > /dev/null $ time cat /tmp/big.bin > /dev/null $ fincore /tmp/big.bin $ free $ echo 3 | sudo tee /proc/sys/vm/drop_caches $ time cat /tmp/big.bin > /dev/null

What you should notice

  • The first cat took several times longer than the second, for the same bytes.
  • After it, fincore shows all 512 pages in memory, and A's kernel view shows a 2 MB page cache.
  • After drop_caches, the first read is slow again.
