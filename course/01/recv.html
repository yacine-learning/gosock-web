Write the receiving half of gosock: wait for a connection and store what arrives in a file. It is what nc -l 9000 > file did, as a program of your own.

The spec

CommandBehaviour
gosock recv ADDR DESTListen for TCP on ADDR (like :9000, meaning port 9000 on every address of the machine). Accept one connection. Write every byte that arrives into the file DEST. When the sender closes the connection, print received N bytes and exit with status 0.
ErrorsAny failure is returned from recv as an error; the given main prints it as gosock: ... and exits with status 1.

main is written. You write the body of recv. The comments name the Go function to use; you write the statements. Check every error, and defer every close. Reference: net.Listen, Accept, os.Create, io.Copy.

Run it by hand once

The checks ran your program on machines of their own. Now run it on yours: B receives, A sends one line with nc.

$ gosock recv :9000 got.txt $ echo "hello gosock" | nc -N $B_IP 9000 $ cat got.txt

What you should notice

  • While it waits, your program appears in B's user space, in the kernel inside a call named accept, and B's kernel holds a socket in state LISTEN.
  • received 13 bytes: twelve characters and the end of line.
  • Your program exited by itself because nc -N announced the end. That is the lesson of the previous lab, seen from the receiving side.
