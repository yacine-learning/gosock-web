What you should know
  • A file descriptor is a slot number in a table the kernel keeps for each process.
  • Each slot points to an open file description: what the thing is (file, socket, terminal) and the offset, where the next read or write starts.
  • The kernel hands out the lowest free number. 0, 1, 2 are standard input, output and error, so a program's first file or socket is 3.
  • Numbers mean something only inside one process. When it exits, every slot is closed for it.
Why a number, and not the file itself

Reading a file takes many system calls: open it, read a bit, read more, close it. Between those calls the kernel must remember which file, how far you have read, and whether you may write. It cannot hand your program the object itself (your program would then be able to change kernel memory), so it keeps the object and gives the program a handle: a small integer, an index into the process's own table.

The same handle works for very different things. A file, a socket and a terminal all answer read and write. That is why io.Copy could join a file to a connection: to the kernel both are file descriptors.

The same thing in simplified kernel C

The real kernel structures with most fields removed:

struct files_struct { // one per process: the fd table struct file *fd[NR_OPEN]; // fd[3] is "file descriptor 3" }; struct file { // the open file description loff_t f_pos; // the offset: the next read/write starts here unsigned f_flags; // read-only, append, ... const struct file_operations *f_op; // read, write, close... for THIS kind of object struct inode *f_inode; // the file (for a socket: the socket's inode) }; // read(3, buf, n) in the kernel, roughly: // struct file *f = current->files->fd[3]; // return f->f_op->read(f, buf, n, &f->f_pos);

The last line is why one read works on files, sockets and pipes: each open file description carries its own table of operations (f_op).

Run this

Start your receiver on B and leave it waiting:

$ gosock recv :9000 big.copy

Set Wire to slow, then send:

$ gosock send $B_IP:9000 /tmp/big.bin

What you should notice

  • On B: 3 is the listening socket, then 4 appears (the connection from Accept) and 5 (the file from os.Create).
  • The file's offset moves as bytes are written.
  • A has its own 3 and 4, and they are different things.
