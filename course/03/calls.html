What you should know
  • A server is four calls: socket (a descriptor for a new, empty socket), bind (an address and port), listen (accept connections, with a queue), accept (wait for one, get a new descriptor).
  • A client is two: socket, then connect, which does the handshake and returns once it is done.
  • net.Listen and net.Dial are these calls, plus a few options.
What each call gives the kernel

socket(AF_INET, SOCK_STREAM, 0): IPv4, a byte stream, the default protocol for that (TCP). The socket has no address yet. bind gives it one; a client usually skips it and the kernel picks a free "ephemeral" port at connect. listen turns the socket into a listening one: from then on the kernel completes handshakes for it, alone. accept takes one finished connection from the queue.

The listening socket never carries data. Each accepted connection is a separate socket, with its own descriptor, buffers and state.

Two objects per socket, in simplified kernel C struct socket { // what the file descriptor reaches (via struct file) socket_state state; // SS_UNCONNECTED, SS_CONNECTED... struct file *file; struct sock *sk; // the protocol's side const struct proto_ops *ops; // inet_stream_ops: bind, listen, accept, connect... }; struct sock { // the network side (struct tcp_sock for TCP) unsigned char skc_state; // TCP_LISTEN, TCP_ESTABLISHED, TCP_TIME_WAIT... __be32 skc_rcv_saddr; __u16 skc_num; // local address and port __be32 skc_daddr; __be16 skc_dport; // remote address and port struct sk_buff_head sk_receive_queue, sk_write_queue; // the buffers int sk_rcvbuf, sk_sndbuf; // their sizes struct request_sock_queue icsk_accept_queue; // listening: finished connections };

Run this

Trace only the network calls (-e trace=network) of your module 1 receiver, then send it a small file:

$ strace -e trace=network gosock recv :9000 got.txt $ strace -e trace=network gosock send $B_IP:9000 /tmp/hello.txt

What you should notice

  • On B: socket = 3, bind, listen, then accept(3, …) waits, and returns 4.
  • On A: socket = 4 (3 is the file), connect, and no bind: getsockname shows the port the kernel chose.
  • Go also called setsockopt: SO_REUSEADDR on the listener, TCP_NODELAY on the connection.
