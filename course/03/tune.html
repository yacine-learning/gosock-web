What you should know
  • setsockopt(fd, level, option, value) changes one setting of a live socket; getsockopt reads it back.
  • SO_RCVBUF sets the receive buffer size, so the window this socket can advertise. Set it before listen (or connect): accepted sockets inherit it.
  • Linux doubles the value you give: half for data, half for its own bookkeeping. getsockopt shows the doubled number.
Options you will meet
Level, optionEffect
SOL_SOCKET, SO_RCVBUF / SO_SNDBUFbuffer sizes (normally tuned automatically by Linux; setting one turns that off)
SOL_SOCKET, SO_REUSEADDRbind a listening port that old TIME_WAIT connections still hold
SOL_SOCKET, SO_KEEPALIVEprobe an idle connection to detect a dead peer
IPPROTO_TCP, TCP_NODELAYsend small writes at once (turns Nagle's algorithm off)

In Go, conn.(*net.TCPConn).SetReadBuffer(n) is setsockopt(SO_RCVBUF), and net.ListenConfig{Control: …} lets you call setsockopt on a listener before listen.

Run this

tinyrecv asks for a 4096-byte receive buffer with setsockopt, then reads it back with getsockopt. What does it read? 40968192131072, the default: the request is ignored.An error: 4096 is too small.

Linux stores twice the request, to leave room for its own per-packet bookkeeping, and reports what it stored.

tinyrecv sets SO_RCVBUF before listen, then reads slowly. Build it, set Wire to slow, and start it in the background on B:

 $ tinyrecv 4096 &

Send the big file, and look at the sender's socket while it goes:

$ nc -N $B_IP 9000 < /tmp/big.bin & $ ss -tnmi

What you should notice

  • B printed "asked for a 4096-byte receive buffer, the kernel gives 8192".
  • During the big transfer, B's receive buffer bar is 8 KB, and on A snd_wnd stays at 8192 or below: B's small buffer limits how much A may send.
