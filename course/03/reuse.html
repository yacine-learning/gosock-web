A bug on purpose: a server that cannot start again right after it stopped.
What you should know
  • A server that closes a connection first leaves it in TIME_WAIT for 60 seconds, and that old connection still holds the server's port.
  • Restarting the server: bind on that port fails with EADDRINUSE, "address already in use", unless the new listening socket has SO_REUSEADDR.
  • Go sets it on every listener; programs written with raw calls, in C or in Go, must set it themselves.
Why the rule is safe

SO_REUSEADDR does not let two programs listen on the same port: a second listener still gets EADDRINUSE. It only lets a new listener coexist with old connections in TIME_WAIT. New connections differ from the old ones in the client's port, so TIME_WAIT keeps doing its job.

The symptom confuses people because it depends on who closed first and on timing: restart after a minute and everything works.

Run this

once greets one client and closes the connection first. Without an argument it does not set SO_REUSEADDR. Build it, then:

 $ once & $ nc $B_IP 9000 $ ss -tan $ once $ once -reuse & $ nc $B_IP 9000

What you should notice

  • After the first greeting, B holds TIME-WAIT 10.0.0.2:9000: the server's side, because it closed first.
  • The second once stops at once: once: bind: address already in use.
  • once -reuse binds the same port next to the TIME_WAIT connection, and greets A.
