What you should know
  • A TCP socket in the kernel (a struct sock) holds its state, both addresses, a send buffer and a receive buffer with their sizes, sequence numbers, the peer's window, timers and counters.
  • ss -tnoemi prints most of it for every socket: -o timers, -e identity, -m memory, -i TCP internals.
  • Recv-Q is data received but not yet read by the program; Send-Q is data written but not yet acknowledged by the peer.
Reading ss -tnoemi
FieldMeans
skmem:(r…,rb…,t…,tb…)receive queue bytes and receive buffer size; send queue bytes and send buffer size
bytes_sent / bytes_acked / bytes_receivedcounters since the connection began
segs_out / segs_insegments sent and received, ACKs included
snd_wndthe peer's last advertised window: how much more it can take
rcv_wndthe window this socket advertised: free room in its receive buffer
rto, rttretransmission timeout and measured round-trip time, in ms
timer:(…)a timer that is running: retransmission, keepalive, timewait
ino, skthe socket's inode number and kernel object

A real Linux prints more (cwnd, ssthresh, pacing_rate…): they belong to congestion control, which these machines leave out.

Where the numbers live, in simplified kernel C struct tcp_sock { // starts with a struct sock, then TCP's own fields struct inet_connection_sock inet_conn; // ... struct sock sk inside u32 snd_una; // oldest byte sent and not yet acknowledged u32 snd_nxt; // next byte to send u32 rcv_nxt; // next byte expected from the peer u32 snd_wnd; // the peer's window -> ss: snd_wnd u32 rcv_wnd; // the window we advertise -> ss: rcv_wnd u32 srtt_us; // smoothed round-trip time -> ss: rtt u64 bytes_acked, bytes_received; // -> ss: bytes_* u32 segs_out, segs_in, total_retrans; // -> ss: segs_*, retrans }; // sk->sk_rcvbuf, sk->sk_sndbuf -> ss: rb, tb // sk->sk_rmem_alloc, sk->sk_wmem_queued -> ss: r, t (and Recv-Q, Send-Q)

Run this

Set Wire to crawl, start a transfer, and look inside both sockets while it runs:

$ gosock recv :9000 big.copy & $ gosock send $B_IP:9000 /tmp/big.bin & $ ss -tnoemi $ ss -tnoemi

Set Wire back to fast to let it finish.

What you should notice

  • On A, Send-Q and t are high: written by the program, not yet acknowledged. bytes_acked trails bytes_sent.
  • On B, bytes_received on one side matches bytes_acked on the other, give or take what is on the wire.
  • rb131072 and tb87040: the default buffer sizes.
